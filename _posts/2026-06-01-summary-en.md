## [Running Python ASGI Apps in Browser via Pyodide and Service Workers](https://simonwillison.net/2026/May/30/pyodide-asgi-browser/#atom-everything) ⭐️ 9.0/10

Simon Willison demonstrated a technique to run Python ASGI apps in the browser using Pyodide and a service worker, enabling full execution of JavaScript in script tags, which was not possible with previous Web Worker-based approach. This breakthrough allows Python web applications with JavaScript-dependent features (e.g., Datasette plugins) to run entirely in the browser without a server, expanding the capabilities of browser-based Python and potentially enabling richer interactive web apps. The implementation uses a service worker to intercept network requests and run the Python ASGI app within Pyodide, executing scripts generated by the app. Demos include a basic ASGI FastCGI app and a full Datasette 1.0a31 instance, with plans to upgrade Datasette Lite.

rss · Simon Willison · May 30, 21:02

**Background**: Pyodide is a port of CPython to WebAssembly that allows running Python packages in the browser. ASGI (Asynchronous Server Gateway Interface) is a standard for async Python web servers and applications, superseding WSGI. Previously, Datasette Lite used Web Workers to run Python but could not execute JavaScript in script tags, limiting plugin compatibility. Service Workers provide a network proxy layer that can handle fetch events, enabling proper script execution.

## [Linux rseq(): Restartable Sequences for Lock-Free Programming](https://justine.lol/rseq/) ⭐️ 8.0/10

The article explains how Linux's rseq() system call enables user-space threads to safely access per-CPU data without mutexes or atomic operations by allowing the kernel to abort and restart critical sections if interrupted. rseq() significantly simplifies high-performance concurrent programming and reduces overhead, making it a key feature for memory allocators like TCMalloc and other performance-sensitive applications. Each thread must register an rseq area before using the feature, and critical section code must be idempotent so it can be safely restarted. The kernel only aborts the sequence if the thread is preempted, not on every context switch.

hackernews · grappler · May 31, 14:38 · [Discussion](https://news.ycombinator.com/item?id=48346019)

**Background**: Traditional lock-free programming often relies on expensive atomic operations or mutexes. Restartable sequences provide a cooperative kernel mechanism where user-space marks critical sections, and the kernel ensures they either complete without interruption or are rolled back and retried.

## [FROST Attack Uses SSD Timing to Spy on User Activity](https://futurism.com/future-society/websites-spying-solid-state-drive) ⭐️ 8.0/10

Researchers have disclosed FROST, a contactless side-channel attack that uses the browser's Origin Private File System (OPFS) and SSD read/write timing to infer which websites or applications a user is accessing, achieving 88.95% accuracy for websites and 95.83% for applications on Mac and Linux. This attack demonstrates a new privacy threat where malicious websites can silently monitor user activities without requiring software installation or user interaction, potentially affecting millions of users. It highlights the need for stronger isolation in browser storage APIs and mitigations against timing-based side channels. The attack was tested only on Mac and Linux systems, but researchers note that Windows is not immune; closing browser tabs after use can reduce risk. The technique relies on the high-performance OPFS storage endpoint introduced as part of the File System API.

telegram · zaihuapd · May 31, 01:55

**Background**: The Origin Private File System (OPFS) is a browser storage endpoint that provides high-performance file operations private to a web page's origin, making it faster than IndexedDB. Side-channel attacks exploit indirect signals, such as timing variations, to infer sensitive information without directly accessing it. FROST (Fingerprinting Remotely using OPFS-based SSD Timing) measures timing differences in SSD read/write operations caused by other applications' data access patterns.
