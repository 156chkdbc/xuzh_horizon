A critical unauthenticated path traversal vulnerability (CVE-2026-53519, CVSS 9.1) has been discovered in Nezha monitoring probe versions below 2.0.13. Attackers can read arbitrary files, including the config.yaml which contains the JWT secret key, by sending crafted GET requests such as '/dashboard../data/config.yaml'. This vulnerability allows unauthenticated attackers to obtain the JWT secret key, potentially leading to full account takeover and unauthorized access to the monitoring system. It affects all Nezha installations running versions below 2.0.13, which is widely used for server monitoring. The vulnerability is a path traversal issue in Nezha's dashboard component, triggered by double-dot sequences in URLs. The CVSS score of 9.1 indicates critical severity. Users should immediately upgrade to version 2.0.13 or later to mitigate the risk.

telegram · zaihuapd · Jun 17, 01:25

**Background**: Path traversal (or directory traversal) is a type of web security vulnerability that allows attackers to access files and directories stored outside the web root folder by manipulating file paths in URLs. JWT (JSON Web Token) is a standard for securely transmitting information between parties; the secret key is used to sign and verify tokens. If an attacker obtains the JWT secret key, they can forge valid tokens and impersonate any user, including administrators.

## [Stop Using JWTs for Browser Sessions](https://gist.github.com/samsch/0d1f3d3b4745d778f78b230cf6061452) ⭐️ 8.0/10

A widely shared gist argues that JSON Web Tokens (JWTs) should not be used for browser-based user sessions, sparking renewed debate over their security and appropriate use cases. This matters because JWT is a cornerstone of modern web authentication, yet its misuse in browser sessions can introduce serious security vulnerabilities, prompting developers to reconsider stateless vs. stateful session management. The criticism focuses on JWTs' inability to be revoked server-side easily, exposure to XSS and CSRF attacks when stored in browser storage, and the assumption that statelessness is always beneficial; the gist also notes that JWT is fine for service-to-service communication.

hackernews · dzonga · Jun 16, 16:49 · [Discussion](https://news.ycombinator.com/item?id=48558147)

**Background**: JSON Web Token (JWT) is an open standard (RFC 7519) for transmitting claims between two parties as a JSON object, commonly used for authentication and authorization. In browser sessions, JWTs are often stored in localStorage or cookies, but unlike traditional session IDs stored server-side, they cannot be revoked without maintaining a blacklist. This has led to security debates, especially regarding stateless vs. stateful session management.
